# 调试工具—无线急停盒 USB Serial 通信协议设计文档

**文档版本：** V1.0  
**适用项目：** WRS Debugger  
**通信双方：** 调试工具 ↔ 无线急停盒  
**运行平台：** Linux PC  
**物理接口：** USB Type-C（无线急停盒）  
**逻辑接口：** USB Serial  
**文档状态：** 设计基线  

## 1. 文档范围与总体约定

### 1.1 目的

本文定义调试工具与无线急停盒之间的 USB Serial 通信设计，覆盖：

- PC 侧 USB Serial 设备发现与连接约定；
- 串口参数；
- 42 Byte 业务帧约定；
- LoRa 通信参数读取与配置；
- GFSK 通信参数读取与配置；
- SDO 读写；
- PIN 读取与配置；
- 出厂默认通信参数及恢复默认；
- 设备识别和当前协议边界。

本文仅描述：

```text
Linux PC 调试工具
       │
       │ USB Serial
       ▼
   无线急停盒
```

不描述 APP、接收板、Sub-1G 无线链路、ROS 2、CDU、SPI 或内部 RS485 协议。

### 1.2 依据

本文以以下文档为依据：

1. 《APP-Sub1G无线急停通讯协议 V1.0》
2. 《急停配置工具迭代1需求 V1.7.0》

其中原协议明确规定：

- 调试工具通过串口为无线急停盒配置 PIN 和通信参数；
- 通信参数读写复用原协议 4.1.5；
- 业务帧固定为 42 Byte；
- 多字节整数采用小端；
- 保留字段发送时置 0。

本文同时纳入项目已确认的补充规则：

1. PIN 请求中 Byte1～6 为 ASCII `"000000"` 时表示读取当前 PIN；
2. 恢复默认通信参数不新增独立命令，而是使用 `0x05` 将对应调制方式的全部默认参数完整写入；
3. 调试工具中的 Device ID 指协议中的无线急停盒设备 ID，不等同于 SDO `Serial Number`；
4. PC 端不依赖固定 `/dev/ttyUSBx` 或 `/dev/ttyACMx`，应自动发现 USB Serial 候选设备并通过只读协议探测确认。

### 1.3 指令范围

| 请求 | 响应 | 功能 |
|---:|---:|---|
| `0x04` | `0x84` | 读取通信参数 / 读取 SDO |
| `0x05` | `0x85` | 配置通信参数 / 写入 SDO |
| `0x07` | `0x87` | 读取 PIN / 配置 PIN |

### 1.4 串口参数

| 参数 | 值 |
|---|---|
| 通信方式 | USB 转串口 |
| 波特率 | 115200 bps |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | 无 |
| 流控 | 无 |

即：

```text
115200 / 8N1 / No Flow Control
```

### 1.5 通用业务帧约定

所有业务帧固定为：

```text
42 Byte
```

约定如下：

- 多字节整数采用 Little Endian；
- 字节数组按原序发送；
- 保留字段发送时置 0；
- Request 的 Byte39 结果码固定为 0；
- Byte40～41 为 CRC；
- CRC 使用 CRC16-XMODEM；
- CRC 计算范围为 Byte0～39；
- CRC 低字节在前。

当前通用结果码：

| 数值 | 含义 |
|---:|---|
| `0x00` | 处理成功 |
| `...` | 详细结果码待补充 |
| `0xFF` | 处理失败 |

### 1.6 事务 ID

通信参数、SDO 和 PIN 操作均使用事务 ID。

规则：

- 事务 ID 为 `uint32`；
- 事务 ID 必须非 0；
- 每次新的独立操作使用新的事务 ID；
- 同一请求重试时保持原事务 ID；
- 响应回显请求事务 ID。

## 2. USB Serial 设备发现与连接约定

### 2.1 背景

无线急停盒运行时通过 USB Serial 与 Linux PC 调试工具连接。Linux 为 USB 串口分配的设备节点不是稳定设备身份，例如同一设备在不同插拔顺序或不同 USB 口下可能分别表现为：

```text
/dev/ttyUSB0
/dev/ttyUSB2
```

或：

```text
/dev/ttyACM0
/dev/ttyACM1
```

因此调试工具不得依赖固定 `/dev/ttyUSBx` 或 `/dev/ttyACMx` 名称。

### 2.2 自动发现流程

调试工具应自动发现当前 PC 上可用的 USB Serial 候选设备，流程定义为：

```text
枚举 USB Serial 候选设备
          │
          ▼
按可用 USB 元数据进行预筛选
          │
          ▼
以 115200 / 8N1 打开候选串口
          │
          ▼
发送只读 SDO 探测请求
          │
          ▼
校验 42 Byte / CRC / Command / Transaction ID / SDO Status
          │
          ▼
确认是否符合无线急停盒协议
          │
          ├── 否：关闭并继续下一候选设备
          │
          └── 是：记录为已发现无线急停盒
```

### 2.3 USB 元数据

硬件到手前，不假设固定的：

- VID；
- PID；
- USB Serial Number；
- Manufacturer；
- Product。

这些字段在当前阶段仅作为可选发现元数据，不作为协议成立的必要条件。

硬件确认后，可增加 VID/PID/Product 等快速预筛选规则，但最终仍应由业务协议探测确认设备。

### 2.4 协议探测

自动发现只允许使用无状态、只读的 SDO 请求，不使用：

- `0x05` 参数写入；
- `0x07` PIN 配置；
- 任何会修改设备状态的请求。

首选探测对象：

| Object Index | 对象 | 权限 |
|---:|---|---|
| `0x001` | Product Code | RO |
| `0x002` | Version Number | RO |
| `0x003` | Serial Number | RO |

在硬件 Product Code 固定值尚未确认前，设备确认依据为：

1. 返回完整 42 Byte 响应；
2. Response Command 为 `0x84`；
3. 事务 ID 与请求一致；
4. CRC 正确；
5. Object Index 地址与请求一致；
6. SDO Status 为 `0x4`（读取成功）；
7. 连续只读对象请求均符合本协议。

硬件到手后，可进一步增加：

```text
VID/PID 匹配
+
Product Code 固定值匹配
+
合法协议响应
```

作为更严格的设备确认条件。

### 2.5 多设备

若自动发现结果为：

- 0 个无线急停盒：报告未发现设备；
- 1 个无线急停盒：可直接选择该设备；
- 多个无线急停盒：应将所有已确认设备提供给上层选择，不要求用户逐个尝试系统串口节点。

USB Serial Number、SDO Serial Number 和 Device ID 是不同概念，不应混用：

```text
USB Serial Number
    USB 枚举层身份，可选，取决于硬件实现

SDO 0x003 Serial Number
    无线急停盒业务对象字典中的设备序列号

Device ID
    无线急停盒协议中的设备 ID
```

## 3. 通信参数读取/配置协议

读取通信参数使用 `0x04`，配置通信参数使用 `0x05`。

Object Index：

```text
Object Index == 0
    读写完整通信参数

Object Index != 0
    操作 SDO
```

响应：

```text
0x04 → 0x84
0x05 → 0x85
```

参数读取成功时，响应返回当前完整参数。

| Byte39 | 结果码 | 见 1.5 | uint8 | / | / |
| Byte40～41 | CRC | CRC16-XMODEM；计算 Byte0～39，低字节在前 | uint16 | / | / |

## 4. PIN 与 SDO 协议

### 4.1 PIN 读取/配置请求

**方向：调试工具 → 无线急停盒**

PIN 读取和配置共用 `0x07`。

项目确认的操作区分：

```text
Byte1～6 = ASCII "000000"
    → 读取当前 PIN

Byte1～6 = 其他合法 6 位 ASCII 数字
    → 配置 PIN
```

帧格式：

| 索引 | 变量名 | 释义 | 数据类型 | 系数 | 单位 |
|---|---|---|---|---:|---|
| Byte0 | 系统指令 | PIN 读取/配置请求（`0x07`） | uint8 | / | / |
| Byte1～6 | PIN 码 | 6 字节 ASCII 数字，每字节为 `0x30～0x39`；`"000000"` 表示读取当前 PIN | uint8[6] | / | / |
| Byte7～11 | 预留 | 固定 0 | uint8[5] | / | / |
| Byte12～15 | 事务 ID | 新的非 0 事务 ID，同一请求重试时保持不变 | uint32 | / | / |
| Byte16～38 | 预留 | 固定 0 | uint8[23] | / | / |
| Byte39 | 结果码 | 固定 0 | uint8 | / | / |
| Byte40～41 | CRC | CRC16-XMODEM；计算 Byte0～39，低字节在前 | uint16 | / | / |

**表 4-1 PIN 读取/配置请求**

由于 ASCII `"000000"` 被占用为读取语义，如果产品需要支持将实际 PIN 配置为 `"000000"`，则会产生协议歧义，需要另行定义操作区分方式。

### 4.2 PIN 读取/配置响应

**方向：无线急停盒 → 调试工具**

读取和配置均使用 `0x87`：

- 读取 PIN 时，Byte1～6 返回当前实际 PIN；
- 配置 PIN 时，Byte1～6 回显配置后的 PIN。

| 索引 | 变量名 | 释义 | 数据类型 | 系数 | 单位 |

| Byte0 | 系统指令 | PIN 读取/配置响应（`0x87`） | uint8 | / | / |
| Byte1～6 | PIN 码 | 读取时返回当前 PIN；配置时回显配置后的 PIN | uint8[6] | / | / |
| Byte7～11 | 预留 | 固定 0 | uint8[5] | / | / |
| Byte12～15 | 事务 ID | 原样返回请求中的事务 ID | uint32 | / | / |
| Byte16～38 | 预留 | 固定 0 | uint8[23] | / | / |
| Byte39 | 结果码 | 见 1.5 | uint8 | / | / |

### 4.3 SDO 数据对象索引

## 6. 需求覆盖与当前边界

### 6.1 调试工具需求覆盖

《急停配置工具迭代1需求 V1.7.0》要求无线急停盒配置支持：

- 显示 Device ID；
- 读取 PIN；
- 配置出厂 PIN；
- 读取通信参数；
- 配置通信参数；
- 恢复默认通信参数。

当前协议覆盖情况：

| 需求 | 协议能力 | 状态 |
|---|---|---|
| LoRa 参数读取 | `0x04 / 0x84` | 已覆盖 |
| LoRa 参数配置 | `0x05 / 0x85` | 已覆盖 |
| GFSK 参数读取 | `0x04 / 0x84` | 已覆盖 |
| GFSK 参数配置 | `0x05 / 0x85` | 已覆盖 |
| PIN 读取 | `0x07 / 0x87`，请求 PIN=`"000000"` | 已覆盖 |
| PIN 配置 | `0x07 / 0x87` | 已覆盖 |
| 恢复默认 | `0x05 / 0x85`，完整写入默认参数 | 已覆盖 |
| SDO 设备信息读取 | `0x04 / 0x84`，Object Index 非 0 | 已覆盖 |
| Device ID 显示 | Device ID 语义已明确为无线急停盒设备 ID | 读取路径待确认 |

### 6.2 Device ID

调试工具中的 Device ID 指协议中的无线急停盒设备 ID。

该值与以下对象不得混淆：

```text
USB Serial Number
SDO 0x003 Serial Number
```

原协议在其他业务帧中将无线急停盒设备 ID 定义为：

```text
急停盒芯片 ID 后 3 字节，按原序发送
```

但当前“调试工具—无线急停盒”串口子协议中没有单独定义 Device ID 查询指令或 Device ID SDO 对象。

因此：

- Device ID 的含义已经明确；
- Device ID 的 USB Serial 读取路径仍需在硬件或协议侧进一步确认；
- 不得使用 SDO `Serial Number` 自动替代 Device ID。

### 6.3 当前尚待确认事项

以下内容不影响现有参数/PIN协议定义，但在硬件联调前仍需确认：

1. 无线急停盒 USB 侧具体设备类型：原生 USB CDC 或 USB-UART Bridge；
2. VID/PID 是否固定且能够唯一筛选无线急停盒；
3. USB Serial Number 是否存在且是否每台设备唯一；
4. SDO `Product Code` 的无线急停盒固定值；
5. Device ID 在调试工具串口链路中的正式读取方式；
6. 业务响应超时值；
7. 最大重试次数和重试间隔；
8. 除 `0x00/0xFF` 外的详细结果码；
9. 固定 42 Byte 且无 SOF/Length 的情况下，串口流发生插入/丢字节后的正式重同步规则。

在上述硬件属性尚未确认前，设备发现采用“USB Serial 枚举 + 只读 SDO 协议探测”的通用方案；硬件到手后可增加 VID/PID、USB Serial Number 和 Product Code 的精确筛选，而不改变业务协议。
